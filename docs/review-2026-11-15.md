# Review of 2026-11-15: what to fix

An independent review of the code (Claude Fable 5.2, at Ido's request) found the problems below.
This file turns each into work for the Claude session that develops Cerebro. Ido asked the review
to leave features still being built alone, so it covers the foundations: the reactive core, the
JSX runtime, the protocol, the host, the app's main process, saving, the language-server pool, the
index, terminals and agents' hooks.

## How to use this file

- **`CLAUDE.md`'s rules apply as for any work.** A fix comes with a test that fails without it,
  run before the fix to see it fail. A change goes through a pull request. A decision that changes
  is recorded in `decisions.md`.
- **Two kinds of item.** "To fix" items are bugs whose fix changes no decision: do them, in the
  order given. "To propose to Ido" items change a decision or reshape shared code: bring Ido a
  short proposal (what, why, what it costs), and build only on his word.
- **What's measured says so,** with the steps, so the same steps can become the failing test. The
  review's scripts weren't kept. Anything not marked measured was read from the code, or is a
  claim.
- **Line numbers are as of commit `ce8bf6a`** (`feat/cut-greyed`, 2026-11-14). Find by the names
  given where they've moved.
- **An item goes when it's done,** as in the backlog.

## To fix

### 5. What the agent's status shows after an interrupt

The turn an interrupt cuts short is kept since 2026-11-15 (decision "Agent turns"): what's left is
its status. Read from the code: it stays "working" after an interrupt, until another hook arrives
(`HOOK_STATES`, `packages/host/src/agents.ts`).

**Measured** (2026-11-15, Claude Code 2.1.325 on Linux, in a pseudo-terminal, with a hook on every
event that logs its name: SessionStart, UserPromptSubmit, PreToolUse, PostToolUse,
PostToolUseFailure, Notification, Stop, StopFailure, SubagentStart, SubagentStop, PreCompact,
SessionEnd, PermissionRequest):

- Esc while `sleep 20` ran through the Bash tool: SessionStart, UserPromptSubmit and PreToolUse
  came before it; nothing at all in the 30 seconds after it.
- Esc while it wrote an answer, no tool: SessionStart and UserPromptSubmit before it; nothing in
  the 30 seconds after it.
- Both times the terminal showed "Interrupted · What should Claude do instead?".

So no hook says a turn was interrupted, and the status stays "working" until the next prompt.
What it shows then is Ido's to say. What the page could go on: an Esc typed into the agent's
terminal while it's working (Esc also closes its menus), or the "Interrupted" line in its output
(Claude Code's words, which may change).

## To propose to Ido

### A. A host that dies goes unnoticed

When a host exits unasked, the app closes its connection (`child.on('exit')`,
`packages/app/src/host.ts:64`) and does nothing else. The page isn't told, its requests fail with
"Connection closed", and the project's terminals, its agents among them, have ended with no word
in their views (read from the code). Nothing in the host catches a rejection nobody handles, which
ends a Node process. To propose: what the page shows (a notification, the terminals saying their
process ended), and whether the app starts the host again, its agents resumed by their session ids
as after a restart.

### B. One source of "these files changed", instead of a timer per view

Seven timers in the page ask the host, each on its own: the open documents, the Project tree, the
repository's state, the Commit window, Agent Changes, the shelf, and the Local History.

**Measured** on Linux, with the host's own code and a `git` that counts: a tree with its root and
20 folders open, `git.changes`, `agent.turns` and `git.state` cost 32 git processes a cycle (21 of
them one `git check-ignore` per folder, 9 of them `git.state`), which is 16 a second while the
window has the focus. Windows wasn't measured; `decisions.md` has a dozen git processes at over a
second there.

Read from the code: every document opened in a session is kept (`documents`,
`packages/playground/src/documents.ts:65`; only a deleted file's is dropped), and its whole text
is read again every 2 seconds, whether a tab shows it or not, and after its project has closed.

"The project tree" marks polling as Claude's choice, open to change. To propose: the host telling
the page which paths changed (from a watcher, or from one status pass per worktree), for the tree,
the documents, the Commit window, the index and item 1 to share. If Ido keeps polling, two steps
change nothing the user sees: one `git check-ignore` for all of a refresh's folders together, and
a document's size and time checked before its text is read. Letting go of documents no tab shows
would change "Editing and saving", where a document outlives its tabs: his call too.

Since item 1 (2026-11-15), the host has a watcher: it watches a worktree while the worktree has
a language server, for those servers only (`LanguageServers` in `packages/host/src/lsp.ts`). Ido
chose a watcher over a status pass there. Its cost is measured in the decision "Language servers,
first part". Made the page's source, it would watch every open worktree, not only those with a
server.

### C. Storage behind one module

29 files of `packages/playground/src` call `localStorage` themselves, each with its own key:
settings at every level, the layout, keymaps, agents' session ids, bookmarks, terminals. "Settings"
and "The layout persists" keep the browser's storage "until the host's local database exists";
each feature since has added a call site to move then. Two windows share the storage and neither
listens for the other's writes, so a window saving a whole layer undoes the other's change (read
from the code). To propose: one module that owns the keys, the reading and the writing, so the
host's database and the settings files can replace it in one place.

### D. Types for the protocol's methods

`serveOn` registers 138 methods and checks each one's parameters by hand. The page has about 170
call sites naming methods as strings, with about 150 casts of what comes back. A changed shape
compiles on both sides; the page's unit tests answer from `FakeHost`, so only the e2e tests would
see it. Names already differ for the same thing: `git.authors` takes `worktree`,
`git.exclusiveAuthors` takes `path`. A failure's code and data stop at the main process (`handle`,
`packages/app/src/ipc.ts:12`): the page gets the message alone. To propose: a map of each method
to its parameters and result, types only, in `protocol`, which `onRequest` and `request` take,
adopted a method at a time.

### E. The index off the host's event loop

The host's one event loop serves terminals and the prompt's hook, and parses the index too: 200
files between yields (`BATCH`, `packages/index/src/worktree.ts:42`), which by `decisions.md`'s
14 s for 5,231 files is about half a second a batch (derived, not measured). The cache is written
whole after each pass that parsed something (0.37 s there). To propose: the index in a worker
thread; the spike measured it on 8.

### F. Where an effect's error goes

An effect that throws makes the write that triggered it throw (pinned by the test "keeps running
other effects when one throws, then throws the first error"). So a view's failing binding can fail
an unrelated action: in `save`, `doc.saved()` is inside the `try`
(`packages/playground/src/documents.ts:297`), and would report "Couldn't save" for a file that was
written (read from the code). Whether errors reach writers or are reported apart is a decision
("The MobX-style API").

### G. The file's text with every language-server question

"Language servers, first part" sends the file's text with each request. Highlights, problems,
folds, structure, markers and completions are asked as one types, each carrying the text through
the app's main process to the host. Not measured. It matters most for the host over `ssh`
(milestone 3). To propose: the text sent once per change, and questions naming its version.

### H. Features as plugins

`architecture.md` has features in `plugins/*`, built against `plugin-api` as a third party would
build them. They're in the page, and `plugin-api` has the contribution points Prettier needed. No
restructuring is asked for: the question for Ido is whether that's still the aim, so
`architecture.md` can say (item 10).

## What the review found sound

So it isn't done again:

- no cycles between packages, nothing depends on the playground, and every `src` import is
  declared;
- no `innerHTML` or the like anywhere, under the page's Content-Security-Policy;
- coverage at 100% per file, with no ignore comments and no retries. What it can't see is time and
  the boundaries between processes, which is where the items above are: each needs its scenario as
  a test.

## What it didn't cover

The features still being built (the newer git dialogs, scratch files, bookmarks, cut and paste,
the Structure and Hierarchy windows); the editor and layout UI packages line by line; the macOS
native module; the e2e tests. Of the backlog's 27 known gaps, 23 are tests that fail now and then
with no cause found: that items 2 and 3 (the host killed, the terminal output's races: both done)
explain some of them is a claim.
